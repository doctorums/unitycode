## Железные правила

### 1. Воркеров нет в этом репозитории

Три воркера (`unitycode-petlya`, `unitycode-analyze`, `unitycode-write`)
живут только в Cloudflare. Единственный источник истины — задеплоенный
код.

**Перед любой правкой воркера — вытянуть реальный код через Cloudflare
MCP (`workers_get_worker_code`).** Не по памяти, не по копии из Files.

Причина: 11.07 копия в Files и память не знали про `cachePeek` и
delta-режим, уже работавшие в проде. Чуть не потеряли.

### 2. DDL — только через одобрение

Чтение БД (`execute_sql`, `list_tables`) — свободно.

Любая миграция схемы: сначала показать файлом → дождаться явного «да» →
только потом `apply_migration`. Никогда в одностороннем порядке.

### 3. PostgREST не видит новые таблицы сам

После создания таблицы через SQL обязательно:

```sql
NOTIFY pgrst, 'reload schema';
```

Иначе REST API **молча** перестаёт писать. Так мы потеряли записи в
`events`.

### 4. `events` — append-only

Не чистить, не изменять, не удалять. Никогда.

### 5. Худший канал — расчётный

Портал обязан работать на слабом LTE, нестабильном VPN, мобильном Safari
iOS. **Шум не теряется никогда.** Любое решение проверяется вопросом:
«что будет, если связь оборвётся ровно здесь?»

Механики, которые это держат, — трогать с осторожностью:
- очередь `uc_weave_queue` в localStorage — пишется **до** сетевого
  запроса;
- идемпотентность по `client_id` (UNIQUE + `Prefer:
  resolution=ignore-duplicates`);
- ретраи с бэкоффом на чтении, тихие fail-safe без затирания экрана.

### 6. Браузер не пишет в базу

Чтение — Supabase REST, публичный ключ, RLS только на select.
Запись — **исключительно** через `unitycode-write` (service-ключ).

Любое предложение, которое даёт клиенту право писать, — отклоняется.

## Стиль работы

- Все правки **аддитивные**. Существующая разметка, стили и функции не
  меняются без явного согласия.
- Визуальные изменения — сначала описать, потом делать.
- Минимальная диффа. Никакого попутного рефакторинга.
- Не считать код неправильным только потому, что сам написал бы иначе.
- Готовый файл — карточкой + краткая сводка изменений. Без
  постскриптумов и напоминаний «проверь актуальность».
