# UnityCode

Портал-протокол: внутренний шум встречается с алгоритмическим поиском связей.
Человек вводит «шум» (мысль, страх, наблюдение), ИИ ищет в нём резонанс,
результат вплетается в анонимную Сеть узлов. Никто не владеет Сетью.

*Некоммерческий научно-художественный эксперимент. Без персональных данных.*

Живёт на **https://unitycode.space** (GitHub Pages, этот репозиторий, ветка `main`).

## Архитектура

```
Браузер (GitHub Pages, vanilla HTML/CSS/JS)
   │  чтение: Supabase REST, публичный ключ (RLS: только select)
   │  запись: ТОЛЬКО через write-воркер
   ▼
Cloudflare Workers (workers.dev)          Supabase (PostgreSQL)
   unitycode-petlya   — генератор            nodes, connections,
   unitycode-analyze  — аналитик             events (append-only),
   unitycode-write    — шлюз записи          linker_log, analysis_cache
```

### Воркеры

В папке `workers/` лежат **снимки** задеплоенного кода — публикация для
форкеров. Источник истины — **Cloudflare Dashboard**: правки катятся туда,
затем снимок в репозитории обновляется. Если снимок разошёлся с продом —
прав прод.

- **`unitycode-petlya`** — генератор Спирали. Движок YandexGPT (творческий).
  `POST { raw_noise } → { interpretation }`.
- **`unitycode-analyze`** — аналитик Паттерна. Движок MiMo (холодный).
  Срезы personal / collective, измерения: язык (`lang`), тон (`angle`),
  изоляция по `user_token`. Результат кэшируется в `analysis_cache`.
- **`unitycode-write`** — шлюз записи, три агента в одном файле:
  1. **Привратник** (`gateCheck`) — сигнал или пустота; fail-closed.
  2. **Distill** — квинтэссенция шума (`essence`) для Материи.
  3. **Связующий** (`runLinker`) — фоново (`ctx.waitUntil`) ищет резонанс
     и сам создаёт связи (`created_by='linker'`), лог — `linker_log`.

  Запись в базу — service-ключ (обходит RLS); браузер писать не может.
  Защита от ботов: Cloudflare Turnstile.

### Устойчивость к плохой связи

Ключевой принцип: портал работает на любом устройстве в любых условиях
сети (слабый LTE, нестабильный VPN, мобильный Safari). Потеря шума
недопустима.

- Очередь вплетений в `localStorage` (`uc_weave_queue`) — пишется **до**
  сетевого запроса, досинхронизируется при возврате связи/на вкладку.
- Идемпотентность по `client_id` (UUID с клиента, UNIQUE в `nodes`,
  вставка с `Prefer: resolution=ignore-duplicates`) — повторная отправка
  не создаёт дубликат.
- Ретраи с бэкоффом на чтении, тихие fail-safe без затирания экрана.

## База

Таблицы: `nodes`, `connections`, `events`, `linker_log`, `analysis_cache`.
Эталонная схема — `schema.sql` (выполнить один раз в Supabase SQL Editor
при разворачивании своего узла; включает RLS). `events` — append-only
журнал: не чистить и не изменять.
