# Как форкнуть UnityCode

UnityCode — не сайт, а протокол. Любой может взять его, поднять свой узел и наполнить
своим смыслом. Сетью никто не владеет. На этой странице — всё, что нужно, чтобы
запустить свой портал, **не разорвав связь с другими форками**.

-----

## Что это и из чего состоит

Три страницы-раздела на агентах — это и есть протокольное меню:

- **Спираль** (`petlya.html`) — генератор. Принимает шум человека → рождает резонанс.
- **Узор** (`implant.html`) — аналитик. Читает граф → тихое наблюдение о связях и один открытый вопрос.
- **Сеть** (`set.html`) — карта узлов на Leaflet.

Плюс вход (`index.html`) — генеративное интро, и контентные страницы (`materials.html` —
«Материя», `kniga.html` — читалка), которые к протоколу не привязаны и меняются свободно.

Думают и пишут три агента на Cloudflare Workers:

- `worker-generate.js` → Спираль. Движок — **YandexGPT**. Контракт: `POST { raw_noise, lang } → { interpretation }`.
- `worker-analyze.js` → Узор. Движок — **MiMo V2.5 Pro**. Контракт: `POST { scope, nodes, connections?, lang } → { interpretation, scope, count }`.
- `worker-write.js` → шлюз записи. Единственный, кто пишет в базу. Контракт: `POST { action, token, turnstile, ... } → { ok }`.

База — Supabase (таблицы `nodes`, `connections`). SQL лежит в `create tables.sql`,
`add connections.sql` и `supabase-rls.sql`.

-----

## Важное про безопасность (это изменилось)

Раньше браузер писал в Supabase напрямую своим ключом — любой мог скриптом наплодить
узлы и связи. Теперь иначе, и это часть архитектуры:

- **Браузер в базу не пишет.** Все записи идут через `worker-write.js`, внутри которого
  лежит **секретный** service-ключ Supabase. Ключ живёт только в воркере, в клиент не попадает.
- **RLS включён.** `supabase-rls.sql` запрещает анониму запись и оставляет только чтение.
  Без него твоя база открыта на запись всему миру — выполнить обязательно.
- **Turnstile** (капча Cloudflare, чаще всего невидимая): write-воркер проверяет токен
  плюс ограничивает частоту через KV. Публичный Site Key лежит в клиенте, Secret Key — только в воркере.
- **Публичный ключ Supabase в клиенте — только для чтения.** Это нормально: RLS не даст им записать.

## Форк по шагам

**1. Форкни репозиторий** на GitHub и включи Pages (Settings → Pages → Deploy from branch → main).

**2. Подними свою базу Supabase** (free tier):

- выполни `create tables.sql`, затем `add connections.sql` в SQL Editor;
- **обязательно выполни `supabase-rls.sql`** — он закрывает запись анониму;
- в Settings → API возьми `Project URL`, публичный ключ (`anon`/`publishable` — для чтения)
  и **секретный** service-ключ (для write-воркера; в клиент не вставлять).

**3. Включи Turnstile** в Cloudflare (раздел Turnstile): создай виджет → получишь
Site Key (публичный) и Secret Key.

**4. Подними три воркера** в Cloudflare (скопируй `worker-generate.js`, `worker-analyze.js`, `worker-write.js`):

- генератор: секрет `YANDEX_API_KEY`, свой `YANDEX_FOLDER_ID` в коде;
- аналитик: секрет `MIMO_API_KEY`;
- шлюз записи: секреты `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `TURNSTILE_SECRET` и привязку KV `RATE_KV`;
- **в каждом добавь свой домен в `ALLOWED_ORIGINS`** (вверху файла, ищи метку «ФОРКЕР»).

**5. Впиши свои данные в страницы** (точные места помечены комментарием вверху каждого файла):

- адреса воркеров: `WORKER_URL` (генератор), `ANALYZE_URL` (аналитик), `WRITE_WORKER_URL` (запись);
- `SUPABASE_URL` и публичный ключ Supabase (для чтения);
- Turnstile **Site Key**.

**6. Проверь** по порядку: открой воркер в браузере (должен ответить `{"status":"ok"}`) →
открой Спираль, отправь шум → придёт резонанс → на карте создай узел/связь (пишется через
write-воркер). Если ответа нет и в консоли **CORS** — забыл добавить домен в `ALLOWED_ORIGINS` (шаг 4).

-----

## Что можно свободно менять

Всё, что делает портал **твоим** и не задевает других:

тексты всех страниц · переводы (`i18n.js` и файлы вида `имя_<язык>.md`) · цвета и шрифты ·
анимации входа · подписи кнопок · вид карты · «Материя» и содержимое Книги · свои адреса
воркеров, домен, ключи.

-----

## Несущая стена — и почему её лучше не двигать

Код открыт, технически переписать можно всё. Но несколько вещей держат твой портал
**совместимым с общей Сетью**. Сломаешь — узел выпадет из консенсуса будущих форков и
перестанет «говорить на одном языке» с другими. Это не запрет — честное предупреждение
о последствии:

1. **Три протокольных пункта меню и имена файлов.** Узор · Спираль · Сеть →
   `implant.html` / `petlya.html` / `set.html`. Подписи и стиль меняй как хочешь; набор
   и имена этих файлов — нет. Так порталы узнают друг друга. («Материя» — контентная
   страница, она вне этого правила.)
1. **Контракты воркеров.**
   Генератор: `{ raw_noise } → { interpretation }`.
   Аналитик: `{ scope, nodes, connections } → { interpretation, scope, count }`, где `scope` ∈ `personal | social | collective`.
   Шлюз записи: `{ action, token, turnstile, ... } → { ok }`.
   Поменяешь формат — твои агенты перестанут стыковаться с чужими.
1. **Схема базы и RLS.** Таблицы `nodes` и `connections`, имена полей (`raw_noise`, `lat`,
   `lng`, `user_token`, `parent_id`, `from_node_id`, `to_node_id`, `status`) и включённый
   RLS (запись — только через шлюз). Другая структура → твои узлы не лягут в общую карту.
1. **`parent_id` — священное поле.** Оно принадлежит будущему третьему агенту —
   Связующему. Заполняется только консенсусом нескольких независимых форков, не руками
   и не одним агентом. Пока — не трогай.

-----

## Почему так

Если тебе интересно, что **внутри** портала — несущую стену ты не сломаешь: тебе показали,
где она. А кто захочет сломать — форкнется в свою ветку, и это нормально: Сеть просто
не примет несовместимый узел. Без центрального арбитра. Только естественный отбор тех,
кто говорит на одном протоколе.
